## Facts that gate the release

- **There is no git remote.** `git remote -v` is empty, so a push needs
  `git remote add origin https://github.com/shiraz-wrld/shilevi.git` first, and the branch has
  no upstream, so the first push must name it (`git push -u origin master`).
- **Vercel builds `vercel-deploy/`.** It is generated by `npm run deploy:sync`; the folder is
  committed, so a source edit is not live until it is synced *and* committed.
- **Production is running an older build.** `https://shilevi-main.vercel.app/sw.js` returns
  404 while `/deliver/apply` answers 200, so the live deployment predates the push stage.
- **The hosted database is ahead of production code.** `0037`–`0039` are applied remotely.
  All three are additive, so this ordering is safe, but the database must never be behind the
  deployed code: the dispatchers call `claim_notification_batch()` from `0039`.
- **The working tree is large and old.** 282 files predate this stage. They are
  several separate stages of work that were never committed, not one change.
