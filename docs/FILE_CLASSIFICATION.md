# File classification and release inventory

Every path in the repository belongs to exactly one class. The classes decide what Vercel builds,
what you apply to Supabase by hand, what stays for verification, and what must never be committed.

The authoritative **per-file** list of the deployment is
[`DEPLOY_MANIFEST.json`](DEPLOY_MANIFEST.json) (path, bytes, SHA-256 for every shipped file,
generated by `npm run deploy:sync`). This document records the policy and the notable findings.

## Classes

### A — Vercel application files

Shipped inside `vercel-deploy/`, which is the Vercel **Root Directory**.

| Path | Notes |
|---|---|
| `src/app/**` | Pages, layouts, route handlers, metadata files (`robots.ts`, `sitemap.ts`, `manifest.ts`, `opengraph-image.tsx`, `icon.svg`) |
| `src/components/**` | Shared layout, cart, admin, legal and SEO components |
| `src/domain/**` | Pure money, commission, order, delivery and eligibility logic |
| `src/lib/**` | Environment contracts, Supabase clients, admin/auth guards, payments, email, rate limiting, security headers, site identity |
| `src/middleware.ts` | Session refresh, private-area redirects, `no-store` on private responses |
| `package.json`, `package-lock.json` | Manifest and the committed lockfile used by `npm ci` |
| `next.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`, `tsconfig.json`, `next-env.d.ts` | Build, style, lint and type configuration |
| `.env.example` | Placeholders only; contains no real value |
| `.gitignore` | Keeps secrets and generated output out of Git |
| `README.md` | Project overview and the deployment pointer |
| `public/**` | Optional. **No `public/` directory exists** in this project; static icons are app-router metadata files (`src/app/icon.svg`), and the manifest and robots/sitemap are generated routes |
| `vercel-deploy/**` | Generated copy of the above; identical content, verified by hash |

- `.env`, `.env.local`, `.env.production`, any `.env.*` except `.env.example`.
- Supabase service-role key, Daraja consumer secret/passkey/security credential, Resend key,
  `NOTIFICATION_DISPATCH_SECRET`, any JWT or private key.
- Uploaded provider documents, identity evidence, customer contact details, database dumps.
- Local logs (`*.log`) and RLS run reports (`reports/`).

None of these exists in the current workspace: there is no `.env` file, and
`npm run secrets:scan` reports no credential, JWT or key material in any tracked file.

## Notable findings from this pass

1. **No `public/` directory.** Nothing was missing: the favicon is `src/app/icon.svg`, and
   `robots.txt`, `sitemap.xml`, the web manifest and the OpenGraph image are generated by app-router
   route files. The deployment therefore needs no static-asset folder.
2. **Two lockfiles exist by design** (repository root and `vercel-deploy/`). Next.js inferred the
   workspace root from the parent and warned during a build of the deployment folder. `next.config.ts`
   now sets `outputFileTracingRoot: process.cwd()`, so each build traces from its own directory.
3. **The archived scaffold was the only duplicated application tree.** It contained a second
   `src/app/page.tsx` and its own configs but was never imported — verified by a repository-wide
   search before moving it.
4. **The deployment copy is byte-identical to the source.** `npm run release:verify` recomputes every
   hash and fails on any drift, so a file edited only in `vercel-deploy/` cannot be released silently.
5. **No SQL ships to Vercel.** Route handlers are application code and do ship; migration files,
   verification SQL and the manual bundle do not.

## Rules for future changes

- Edit `src/`, configuration or documentation in the **repository root**, then run
  `npm run release:sync` and commit the regenerated bundles.
- Never add a credential to `.env.example`, source, a test fixture or documentation.
- Never add a migration by editing an applied file: add the next numbered migration.
- Never delete a test to make a check pass; fix the behaviour or record the blocker.
